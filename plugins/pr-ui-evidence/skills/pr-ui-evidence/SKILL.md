# PR UI証跡（before/after）

PRの変更が画面にどう影響するかを、レビュアーが一目で確認できるbefore/afterのスクリーンショットとして残す。**撮影と整理が役割で、見た目の良し悪しの判定はしない**（判定が必要なら`ui-verify-loop`を使う）。

## 前提

- 対象プラットフォームの操作スキル（Android: `android-emulator-operate`、iOS: `ios-simulator-operate`）が使えること。操作方法・サンドボックスの扱い・未導入時の案内はそれらに従い、ここでは重複して定義しない。
- `git`と`gh`が使えること。作業ツリーに未コミットの変更がある場合は、ブランチ切り替えで失われないよう、先にユーザーへ確認する。
- アプリのビルド・起動方法はプロジェクトごとに違う。READMEやCLAUDE.md/AGENTS.mdを見ても分からなければ、ユーザーに聞く。

## 手順

### 1. 対象PRと比較元を決める

- PR番号またはブランチが指定されていなければ、現在のブランチのPRを`gh pr view --json number,baseRefName,headRefName,url`で調べる。無ければユーザーに聞く。
- before = PRのベースブランチ（通常は`baseRefName`）、after = PRのブランチ。

### 2. 影響する画面を推定する

1. `git diff --name-only <base>...<head>`で変更ファイルを一覧する。
2. UI以外（ロジック・テスト・CI・ドキュメントのみ）の変更で、見た目に影響しないと判断できれば、**その旨をユーザーに伝えて終了する**。無理に撮らない。
3. UIに関わる変更ファイル（画面・ウィジェット/ビュー・レイアウト・テーマ・文言/リソース・画像）から、**影響する画面を最大5つ程度の候補**に絞る。共通部品やテーマの変更は影響範囲が広いので、代表的な画面に絞る。
4. 候補と、各画面に到達する操作手順（タップ順・必要な状態）を**ユーザーに提示して確認する**。到達手順が分からない画面は推測せず聞く。確認が済むまで撮影に進まない。

### 3. 撮影する（before → after の順）

プラットフォームごとに、固定の条件で撮る。条件が違うと差分がノイズになる。

- 同じ端末・同じOS・同じ向き・同じ言語/外観モード（ライト/ダーク）を使う。
- 毎回アプリを初期状態から起動し、同じ手順で同じ画面へ到達する。データが日時などで変わる場合は、その旨をメモする。
- 保存先は`.gitignore`済みのディレクトリ（例: `work/pr-evidence/<PR番号>/`）。無ければユーザーに確認する。ファイル名は`<画面名>_before.png` / `<画面名>_after.png`。

手順:
1. `git switch <base>`（またはworktree）→ ビルド・インストール・起動 → 各画面へ到達してスクリーンショットを`*_before.png`として保存。
2. `git switch <head>` → 同様に`*_after.png`を保存。
3. 元のブランチに戻す。

ベース側にその画面が存在しない（新規画面）場合、`before`は「なし（新規）」とする。

### 4. 証跡のMarkdownを作る

`work/pr-evidence/<PR番号>/evidence.md`に、PR説明文へそのまま貼れる形で書く。

```markdown
## UI の変更(before / after)

撮影条件: <端末> / <OS> / <ライト|ダーク> / <言語>

### <画面名>(<到達手順>)
| before | after |
|---|---|
| ![before](<画像URL>) | ![after](<画像URL>) |
```

- 画像のURLは手順5で確定する。確定までは相対パスのプレースホルダにしない（壊れたリンクを貼らないため）。
- 見た目が変わっていない画面は、変わっていないと明記して載せるか、載せない。変化があるかのように書かない。
- 「何が変わったか」の説明は、スクリーンショットから**実際に見える差分**だけを書く。コードから想像した差分を書かない。

### 5. 画像のホスティングとPRへの反映（外部への公開なので確認する）

`gh`にはPR本文へ画像を直接アップロードする機能がない。次のどれにするかを**ユーザーに確認してから**実行する。リポジトリが公開の場合、画像も公開される点を伝える。

| 方法 | 内容 |
|---|---|
| 専用ブランチへコミット | `pr-evidence`のようなorphanブランチに画像だけをpushし、raw URLで参照する。公開リポジトリでは誰でも見られる。非公開リポジトリのraw URLはログイン中の閲覧者にだけ表示される |
| PRコメントに手動添付 | 画像をGitHubのWeb UIでコメント欄にドラッグ&ドロップしてもらう。こちらでは自動化できない |
| 画像は載せない | ローカルの`evidence.md`と画像を渡すだけにする |

PR本文の更新は`gh pr edit --body`で上書きする前に、現在の本文を取得して**既存の本文を残したまま**証跡セクションを追記（既に同じ見出しがあれば置換）する。実行前に最終的な本文をユーザーに見せて確認を取る。

## 注意

- スクリーンショットに個人情報・秘密情報（メールアドレス、トークン、本番データ）が写っていないか、公開前に確認する。写っていたら載せない。
- 撮影できなかった画面（到達不能・ビルド失敗など）は、確認済みとして扱わず、証跡に「未撮影」と理由を明記する。
